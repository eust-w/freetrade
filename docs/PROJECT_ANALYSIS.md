# 项目分析与开源整理

分析日期：2026-10-24。对象为本地 FreeTrade 原型、127 份保留运行日志和当日公网读取结果。

## 项目实际是什么

项目是一套规则驱动的 A 股研究页面生成器。Python 负责采集和排名，HTML/CSS/JavaScript 展示 Top10 与启发式区间，Shell 执行刷新、复制和连通性检查。现有代码没有模型训练、LLM 调用、回测引擎、券商接口或自动下单模块。

主要价值在于将研究筛选与低成本静态交付串起来。它能解释分数来源，但尚不能证明因子有效性或交易收益。

## 原型发现与公开版本处理

| 发现 | 影响 | 本次处理 |
| --- | --- | --- |
| SSH 目标、密钥位置、机器目录写死 | 无法迁移且泄露部署信息 | 从公开导出中移除，使用环境变量 |
| 刷新写出卡片型 CSV，回退却要求拆分价格列 | 成功结果无法可靠作为下次缓存，可能退回旧 seed | 统一为校验后的 JSON 快照 |
| 扫描器输出目录与刷新器查找目录不同 | 最新候选缓存可能未被读取 | 发布路径统一，真实成功快照单独管理 |
| 每次降级重新生成“更新”时间 | 容易把页面生成当成行情更新 | 生成时间、数据日期和状态分开 |
| 降级时固定成交额、上涨数与近涨停数 | 历史统计容易被误认成当日行情 | 面板改为模型权重，去除固定行情判断 |
| 财报和历史起点写死 | 日期推进后含义变化 | 显式配置报告期间与年度；保留边界文档 |
| 标题含 AI，但没有 AI 推理链路 | 容易误导功能预期 | 按规则型研究工具说明 |
| 个别证券被人工指定风险描述与目标倍率 | 缺乏可维护证据且难推广 | 不公开原始指控，排除码由用户配置；移除个股特例倍率 |
| curl 打印状态但不严格校验内容 | 200 页面可能是旧文件，HTTP 错误也可能未让旧脚本失败 | 必需链接与预期文件字节一致性检查 |
| 字符串拼接进入脚本和 innerHTML | 恶意数据可能变成页面内容注入 | 先 HTML 转义，再安全 JSON 序列化并回归测试 |
| 未有适合新环境的入门路径 | 依赖外部行情才能看到界面 | 默认标准库离线演示 |
| 缺少完整成功台账 | 无法把日志缺失解释为成功或失败 | 发布观察状态，unknown 保留为未知 |

## 保留的限制

- 数据源接口不稳定；历史日志中 fallback 占多数。公开版不声称已经恢复实时源稳定性。
- API 没有跨来源一致快照；分页过程中变动可能导致拒绝采集。
- 财务取数没有严格按历史时点复原，不能直接拿来做无前视偏差回测。
- 不同板块涨跌停规则不同，扫描器近涨停统计只是统一阈值近似。
- 当前长期区间与短期区间都是启发式公式，没有含费用、滑点与停牌约束的收益验证。
- 候选筛选仍受幸存者偏差、数据缺失、跨行业可比性和选择范围影响。
- 没有交易日历、缓存最大寿命策略或任务锁，调用方需要补上调度约束。
- 财报字段的内部旧名称保留兼容，阅读时应以配置期间为准。
- 部分非核心板块数据接口失败仍会中断整轮采集，这是后续可拆分的失败域。

## 建议演进顺序

1. 为每个数据源记录独立时间戳、字段契约、可接受缺失率与缓存 TTL。
2. 建立可复现历史样本、交易日历、费用和滑点模型，先证明方法再讨论收益。
3. 拆分非核心数据源失败域，增加总时限与调度锁。
4. 再考虑多提供方、持久化数据库和完整观察面板。
